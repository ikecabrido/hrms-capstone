P11Integrate with the HRMS
Another module calls an endpoint, or the module publishes an outcome.

Process
The API key presented in the request header is validated before any business logic runs; inbound payloads update the corresponding records, and outbound requests return learning outcomes filtered by learner, course or status. Every accepted call is recorded.

Read/write discipline: each table group has exactly one owning process. P2–P8 write only within the ld_ tables they own; P1 reads the shared HRMS tables and never writes them; P11 never touches a counterpart module's tables and only exchanges representations.

Security & Audit Flow

Where control is applied on every path
Sign-in → session role Page router checks role membership PDO prepared statements on all SQL X-API-Key validated before business logic Significant actions → ld_audit_log Integration calls → ld_integration_log CSRF helper available via classes/csrf.php
Unauthenticated integration calls are refused before any data is read or written. Access outside the resolved role's page set is not routed, and the page does not appear in that role's navigation. Because each accepted integration call is recorded, the movement of learning data between modules can be reconstructed afterwards.
